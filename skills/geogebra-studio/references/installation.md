# Installation and troubleshooting

Use an Agent Skills-compatible installer against `YZDame/GeoGebra-Studio`, selecting `geogebra-studio`, or copy the entire `skills/geogebra-studio` directory (not just SKILL.md) to the agent's skills directory.

The GitHub checkout must include `scripts/geogebra-studio.cjs` and `runtime/dist/cli.js` alongside this SKILL.md. Node.js >=22.12 is required; check by running `node "<SKILL_DIR>/scripts/geogebra-studio.cjs" doctor`. If runtime assets are absent, use a packaged npm/Plugin distribution or build from a checkout using `npm ci && npm run build`; do not silently claim installation succeeded.

No MCP or Chrome service is needed. When the agent client can open loopback URLs, run the bundled `preview --input "<ABS_HTML>" --workspace "<ABS_WORKSPACE>"` command by default. Open the returned URL in the browser sidebar or tab and put it first in the reply as a clickable interactive preview link. Keep the process running after the reply. It serves one HTML snapshot, so restart it after modifying that file. Stop it when the preview is no longer needed. A static HTML file-preview pane can restrict external scripts even if a regular browser works; do not treat that pane as browser verification. The preview command does not override client policies: when an access check rejects navigation, report that restriction instead of switching transports or tools to evade it.

Include the generated HTML as a separate download. If loopback preview is unavailable, tell the user to download the HTML and open it directly in Chrome, Safari, or another regular browser. Both viewing paths require access to the official GeoGebra engine online. With the Skill installed, HTML generation itself can run offline. Confirm `window.geogebraStudio.status === "ready"` and the visible drawing before claiming successful rendering.

`GeoGebra failed to load` is an engine bootstrap failure; inspect network/CSP errors in the intended browser. A terminal CDN check cannot prove client access. `Command N failed` means the engine loaded and the construction must be checked instead. A browser without scripting access can display the diagram, but the agent cannot claim a programmatic readiness check. Always state when client rendering has not been verified.

For the Codex Plugin convenience installer, use the published npm version's `install` command; after install restart the client session. This is an optional distribution mode rather than a dependency of Agent Skills.

## DeepSeek Harness

DeepSeek Harness loads this Skill from disk. The published frontmatter stays unchanged: `name` is the kebab-case `geogebra-studio`, `description` is present, and there are no legacy camelCase invocation keys (`disableModelInvocation`, `modelInvocable`, `userInvocable`). Optional `whenToUse` is omitted on purpose. The DeepSeek Harness catalog routes on `name` and `description`; `whenToUse` is provider metadata and is not shown to the model. Leaving the frontmatter as published keeps the same file valid for Claude, Codex, Cursor, and `npx skills`.

The Agent Skill and the DSH plugin are different packages. Use `npx skills add YZDame/GeoGebra-Studio --skill geogebra-studio` for the Skill. The plugin contributes its own copy of this skill, so installing it makes `npx skills add` unnecessary in DeepSeek Harness. Without `-g`, including a non-interactive run, the CLI writes a full copy to `./.agents/skills/geogebra-studio` in the current directory. With `-g`, or Global when the installer asks, that copy is `~/.agents/skills/geogebra-studio`. DeepSeek Harness already scans both, plus `~/.dsh/skills` and a workspace `.dsh/skills`. Invoke the installed Skill with `/geogebra-studio`.

The DeepSeek Harness plugin is published as `dsh-geogebra-studio`. Install it with `dsh plugin --profile web add dsh-geogebra-studio`; when testing a branch, use `dsh plugin --profile web add ./plugins/dsh-geogebra-studio` or the quoted GitHub path. Then restart `dsh web`. The plugin registers `geogebra_build`, `geogebra_preview` and `geogebra_export`, contributes the `geogebra-studio` skill itself, and adds a `sidebar.footer.action` quick-start panel. Installing the plugin replaces the separate `npx skills add` step in DeepSeek Harness. Do not run `dsh plugin add` on the repository root, on `@lydt/geogebra-studio`, or on this skill directory. On Windows, if `&path:` is stripped by `cmd.exe`, use the checkout path.

A manual install copies the entire `skills/geogebra-studio` directory, including `SKILL.md`, `scripts/`, `references/`, and `runtime/`, to `~/.dsh/skills/geogebra-studio` or `~/.agents/skills/geogebra-studio`. Opening this repository as a workspace does not discover `skills/geogebra-studio/` because discovery is one level deep. Copy the whole folder to `.dsh/skills/geogebra-studio` in that workspace. This repository does not ship a symlink: Git on Windows often materializes symlinks as plain text files, and `.agents/skills` is already the install path used by Codex, Cursor, and `npx skills`. The existing `.agents/plugins` record is only the optional Codex marketplace entry.

Node.js >=22.12, file and shell access, and the HTTP preview are the same requirements as for other clients. Prefer the loopback preview when the client can open it. GeoGebra Studio is an independent project and is not affiliated with GeoGebra.
